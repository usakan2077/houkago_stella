# おまけ完走キャンペーンの準備

2026-10-30。公式サイトを基本とし、既存プレイヤーにも対応する方針。

応募対象は日本国内在住の方に限定する（2026-10-31ユーザー決定）。国籍・プレイ言語は問わず、日本語・英語どちらのプレイも対象。ゲームと両LPのバナー・応募ルールに日英で明記する。賞品はAmazon.co.jpギフトカード5,000円分。

## 今回の実装

- おまけの最終エンドカードで128ビットの内部識別コード・ランダムな五七五の合言葉・クリア日時を作る。画面と投稿文には川柳と日時を表示する。途中で本編に戻った場合は発行しない。
- 「感想を添えてXに投稿」はコード・日時・公式アカウント・ハッシュタグ・作品URLの入った編集画面を開く。自動投稿はしない。感想は本人が書き足す。
- コピー機能と、コード・日時を含む画面のスクショを併用できる。投稿ボタンで画像を自動添付する機能はない。
- 最新1件を `vn_bonus_clear_receipt` に保存し、タイトル画面の「おまけのクリア記録」から開き直せる。同じ到達処理の再実行ではコードとイベントを増やさない。別の周回でクリアすれば新しいコードになる。
- GA4送信が失敗してもクリア画面と投稿は使える。保存を拒否された環境でもその画面からの投稿・コピーは使えるが、後日の再表示は保証できない。
- コードは実行時に生成する。共通の合言葉や実際の発行済みコードをGitに保存する方式ではない。
- 累計プレイ時間とオールスキップ使用履歴を別の `vn_play_history` に保存する。画面や投稿文には出さず、クリア記録の保存データとGA4送信に含める。
- クリア画像はゲーム画面全体に元の縦横比で表示し、川柳・日時・投稿ボタンは小さめの半透明パネルに重ねる。「クリア情報を隠す／表示」でメッセージとパネルを開閉でき、開閉ではコードを再発行しない。

### プレイ時間とスキップ履歴（2026-10-31追加）

公開用の合言葉は「完走川柳」。`clear-phrase.js` の5音・3音・3音・5音の単語から、5音／3音＋が＋3音／5音に組み合わせる。全角スラッシュ区切りの1行で表示・コピー・投稿・保存し、GA4には `clear_phrase` として送る。32語ずつ4組で1,048,576通り。促音・撥音は1音、拗音を使わない語彙に限定し、音数をテストする。季語や詩的な意味の整合性は求めない。

内部の `clear_code` は128ビットのまま保持する。同じ川柳が偶然出る可能性があるため、川柳だけで応募を一意に決めず、`cleared_at` と内部IDを合わせて確認する。川柳のない旧記録は、再表示するときに元のIDから同じ川柳を導いて保存する。元の識別コード・クリア日時・プレイ記録は変更しない。古いセーブ内のクリア記録にも同じ処理を行う。

旧記録の川柳への対応付けは、GA4に `bonus_clear_phrase_assigned` として内部ID・川柳・元のクリア日時を送る。これは現在行った表示形式の更新記録であり、新しい `bonus_clear` を送ってクリア回数を増やすものではない。すでに川柳がある記録では再送せず、保存できない場合も同じ画面内で重複送信しない。

スキップ対象の初期設定は「既読のみ」。保存済みの設定があればその選択を維持する。

| イベントパラメータ | 内容 | GA4のカスタム定義 |
| --- | --- | --- |
| `play_time_seconds` | 計測開始後の累計プレイ時間、秒単位・整数 | カスタム指標、測定単位「秒」 |
| `all_skip_used` | 一度でもオールスキップを使ったら1、未使用は0 | イベントスコープのディメンション |
| `unread_skip_count` | スキップで自動送りした未読の台詞の累計件数 | カスタム指標、測定単位「標準」 |
| `play_tracking_started_at` | このブラウザーで計測を始めた日時、ISO 8601 UTC | 必要に応じてイベントスコープのディメンション |
| `play_history_partial` | 導入前のプレイ記録がある場合や保存エラーが起きた場合は1、それ以外は0 | イベントスコープのディメンション |

時間は本編・おまけ・エンディングを含め、ゲーム進行中かつタブが表示されている時間を数える。タイトル・OP待機・非表示タブ・最後のクリア画面での投稿待ちは数えない。長いタイマー停止は端末のスリープ等と区別できないため加算しない。表示したままの放置や設定画面での滞在は含まれるため、読んだ時間そのものではない。約10秒ごととページ非表示・離脱・クリア時に保存する。ブラウザーの強制終了では直近の未保存分が失われ得る。

スキップ設定を「すべて」に変えただけでは使用済みにせず、実際にスキップを開始したときに記録する。既読のみのスキップは対象外。使用中に対象を「すべて」に切り替えた場合も記録する。履歴はセーブ・ロード・新しい周回・進行状況の初期化でも巻き戻さない。ブラウザーの保存データを消せば消える。複数タブの保存では既存の累計と使用済みフラグを読み合わせるが、ブラウザー側の保存は厳密な排他処理や本人確認にはならない。

導入前のプレイ時間・スキップ履歴は復元できない。過去のセーブ・既読・Good End記録を検出した場合は不完全な時間として扱う。新しい計測機能の導入前に発行したクリアコードにも、後から時間を補完しない。オールスキップには既読部分の再走も含まれ得るため、フラグ1や時間の短さだけで失格にしない。

未読スキップ件数は、表示前に未読だった登場人物・主人公の台詞が、スキップのタイマーで自動送りされた時点で加算する。地の文、既読の台詞、既読のみのスキップで停止した未読行、自動送り前にスキップを解除した行は数えない。各行で保存せず、時間の定期保存と合わせて書き込み、未保存の件数が50件に達した場合も保存する。以前の形式の時間・使用フラグは維持し、未読スキップ件数のない記録は0件から計測を始め、不完全な履歴として扱う。

## GA4側で開始前に行うこと

送信イベントは `bonus_clear`。既存の `_trackEvent` を通し、`clear_code`、`clear_phrase`、`cleared_at`（ISO 8601 UTC）、`game_version`、上記5項目と、既存共通の `game_title`、`language` を送る。時間とフラグはコードを発行した時点の値で固定する。Xアカウントや感想は送信しない。

1. 管理 → カスタム定義で、`clear_code`・`clear_phrase`・`cleared_at` を**イベントスコープ**のカスタムディメンションに登録する。表示名は「おまけ内部コード」「完走川柳」「おまけクリア日時」など。パラメータ名は上記の通り完全一致させる。
   追加の時間・スキップ履歴も上表の区分で登録する。時間はディメンションではなくカスタム指標とする。[カスタム指標の公式手順](https://support.google.com/analytics/answer/14239619?hl=ja)
2. 公開後に運営側でクリアし、実際のGA4にイベントが届き、コードと時刻を参照できることを確認する。ローカル自動テストは外部送信を遮断し、送信関数へ渡した値を確認しているため、実プロパティへの受信までは確認していない。
3. 探索でイベント名を `bonus_clear` に絞り、川柳・内部コード・日時を並べて確認する。旧記録から変換した川柳は `bonus_clear_phrase_assigned` も確認し、内部IDで元のクリア記録と照合する。開始前に定義し、レポートへの反映時間を見込んでおく。データ保持期間も応募締切から抽選までをカバーする設定か確認する。

コードと時刻は値の種類が多いディメンションなので、件数が増えると集約・サンプリングなどで個別の記録を取り出しにくくなる。個別照合を続けるなら、開始前にBigQueryエクスポートを設定するか、別途サーバーの応募台帳を設ける。BigQueryも未送信イベントを復元するものではない。

公式資料：[イベントスコープのカスタムディメンション](https://support.google.com/analytics/answer/14239696?hl=ja)、[カーディナリティ](https://support.google.com/analytics/answer/12226705)、[データの鮮度](https://support.google.com/analytics/answer/11198161)。

## 不正対策としてできることと限界

これは応募とプレイ記録を照合する補助機能であり、クリアの認証機能ではない。

- コードと記録された日時が一致するかを見ることで、共通合言葉の丸写しや、存在しないコードでの応募を見つける材料になる。
- ブラウザーの状態、端末時刻、保存データは編集でき、GA4イベントもブラウザーから偽造できる。実装を調べた人の不正や、自動進行、複数アカウントでの応募は完全には防げない。
- 公開されたコードやスクショはコピーできる。今回はコードをXアカウントに認証付きで結び付けていない。同じコードの応募が重なったら、自動で最初の投稿者を正当と決めず、本人への確認を行う。
- スクショも編集できるため、それだけで不正が不可能になるわけではない。
- GA4は広告ブロック・通信失敗・計測設定などで欠測し、反映も遅れる。記録がないことだけで失格にしない。投稿時刻との厳密な一致も求めず、クリア後に日を置いて投稿する人を認める。

より強く防ぐ場合は、サーバーでコードを発行し、一度だけ応募に使える台帳とX投稿者の照合を追加する。その場合も、人が全編を読んだことの完全な証明にはならない。

## 募集の流れの案

賞品はAmazonギフトカード5,000円分×2名、計10,000円。ユーザー指定の締切は2026年12月31日23:59 JST。開始日・告知ポストURL・抽選日・送付予定日は未確定。

### バナーと案内ダイアログ

ゲームのタイトル下部、通常LPとAI制作LPのヒーロー直後にバナーを設置。クリックで共通の告知画像・応募方法・既存プレイヤーへの案内・抽選と連絡のルールを開く。日英表示、スマホ幅、Escape・閉じるボタン・背景クリックによる終了に対応。

ゲームのタイトルではサムネイルと賞品の詳細を表示せず、下の黒帯にバージョン情報と同じ40px高の文字ボタンを置く。開催中の文言は「完走キャンペーン開催中！」。開催前・終了後は状態に合わせた短い文言にし、詳細はクリック先に表示する。

LPでは告知画像を小さなサムネイルにせず、独立した広いセクションに表示する。PCでは画像と案内を横並び、スマホでは画像を上段いっぱいに表示し、常に元の縦横比を保って全体を見せる。ゲームのネイティブダイアログはカスタムカーソルより前面に出るため、開いている間はOSのマウスポインターを表示し、閉じると元のカスタムカーソルに戻す。

期間と告知URLは `campaign-config.js` に集約。開始は告知ポストIDの投稿時刻に合わせた `2026-11-02T22:43:30.500+09:00`、告知URLは https://x.com/houkago_stella/status/2117251255106261117 。締切は `2026-12-31T23:59:59.999+09:00`。開始前・開催中・締切後の表示は日付から切り替える。開始日・告知URLが未設定の場合は「開催準備中」とする。

告知画像は組み込みimagegenで公式ポスターとタイトルロゴを参照して生成した。ゲーム用は `assets/campaign/clear-campaign-v1.webp`（約270KB）、原画と使用プロンプトは隣の素材リポジトリ `assets-src/campaign_20261031/` に保存。バナー画像は遅延読み込みにし、元の大きなPNGをゲームの初期読み込みに追加しない。

1. 公式 `@houkago_stella` をフォローし、キャンペーン告知をリポストする。
2. 公式サイトでおまけの最後まで遊ぶ。
3. 最後の投稿ボタンから、コード・クリア日時・一言感想を添えて投稿する。スクショでコード・日時を示してもよい。感想は肯定的でなくても同じ当選確率にする。
4. 締切後に応募を整理し、1人1口に揃えて無作為抽選。当選候補2名と補欠を選び、応募投稿・フォロー・リポスト・クリア記録を確認する。
5. 当選候補に公式アカウントからDM。7日以内に返答がなければ補欠へ連絡する。ギフトコードは公開せず個別に送る。

通常リポストと感想投稿の2操作を減らすなら、「告知の引用リポストに感想を付ける」方式も候補。ただし今回のボタンは作品の感想投稿を開くもので、告知の引用・通常リポストを自動で行わない。告知の投稿URLが決まった段階でどちらにするか統一する。

X検索だけでは応募を拾いきれない場合がある。公式へのメンションを含め、運営側の応募一覧を作る。必要に応じて投稿URLを受け付けるフォームを加える。複数アカウント応募や同じ投稿の連投は認めず、リポスト回数で当選確率を上げない。[Xのキャンペーンガイドライン](https://help.x.com/en/rules-and-policies/x-contest-rules)

## 既存プレイヤーへの対応

現在、おまけは3人全員のGood Endを見た後、第4章冒頭の分岐から入る。未プレイの人には応募までの負担が大きいため、告知ページで条件と入り方を案内する。

- 公式サイトで遊んだ人は、既存のクリア記録と分岐前のセーブを使っておまけを再プレイすれば、新機能でコードを受け取れる。
- 過去のクリアにさかのぼってコードやGA4記録を作ることはしない。
- 他サイトでクリアした方への問い合わせ誘導と保存データの共有に関する説明は、ユーザー指定で応募案内から削除した。別受付の設置は今回の公開準備の前提にしない。
