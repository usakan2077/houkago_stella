# 進行に合わせた読み込みと素材キャッシュ

ver 1.4.4（2026-10-27）。本文や素材の内容は変更せず、取得の時期と再利用方法を変更した。

## 読み込みの順序

- 初回のロード画面では、独白背景と開始ラベルの最初の背景だけを待つ。全背景・全CG・全表情は走査しない。
- フォントは遅延取得へ回さない。Google Fontsのスタイルシート完了を確認し、ウォームアップ文字と実際の本文に必要な日英のフォントを`document.fonts.load()`で明示取得してから開始可能にする。8秒以内に揃わない、取得失敗、Firefoxで外部フォントを使わない場合は、そのページではシステムフォントへ固定し、遅れて届いたフォントで台詞の幅・改行が変わることを防ぐ。言語切替時も新しい本文の文字を確認する。
- 章扉の画像はNEW GAME後に取得する。タイトルの背景・ロゴは表示時に取得する。
- 本編の実行位置から40命令先まで先読みする。通常ジャンプは追い、選択肢の各行先は12命令、1回につき合計8ラベルまでに制限する。
- 画像の同時取得は2件。現在必要な画像を、待機している先読み画像より優先する。
- 各背景・立ち絵・表情・CGは、必要なら取得完了を待ってから命令を実行する。遅れて完了した処理は進行トークンで無効化し、タイトルへの復帰や別場面への移動を巻き戻さない。
- セーブ復元では、そのセーブに記録された背景・CG・立ち絵を優先取得してから本文へ戻る。
- 先読みの画像は8秒、現在必要な画像は30秒でタイムアウトし、失敗を永久に記録しない。通常の画像表示の代替処理へ進み、後の取得を再試行できる。
- ページ内で明示的に保持する読み込み済みImageは16枚まで。全表情をデコードしたまま保持しない。既存の台詞ボイスの3台詞先読みとメモリ上限は維持する。

## 同一バージョンの永続キャッシュ

`stellaAssetURL()`が素材のURLへ`_stella_v=VN_CONFIG.version`を付ける。個別CGの`v=`修正番号はそのまま保持する。

`asset-cache-worker.js`は同じ配信ディレクトリの`assets/`にある、バージョン付きGETだけを対象にする。画像・音声・BGM・音声パックなどを、バージョン別のCacheStorageに保存する。同じバージョン・同じURLの再訪では保存済みレスポンスを優先し、時間経過だけを理由に再取得しない。大きな動画はCacheStorageへの全量書き込みが現在の画像・音声と競合しないよう、通常のストリーミングとHTTPキャッシュに任せる。

HTML・プログラム・本文データはこのキャッシュに入れない。本文・シナリオは既存のバージョン付き`no-store`取得を継続する。新バージョンは別の素材URLとキャッシュになり、古いタブの素材キャッシュと混ざらない。キャッシュ名は配信先のパスを含むため、同じホスト上の別作品と共有しない。旧バージョンは別タブとの共存のため自動削除せず、ブラウザの容量管理に委ねる。

音楽のRangeリクエストは、完全なキャッシュがある場合に必要な範囲だけ返す。206の全量レスポンスは保存できるが、部分的にしか届いていない音楽は永続キャッシュに入れない。

Service Workerやストレージが禁止されている環境では通常のネットワーク取得へ戻る。HTTPSまたはlocalhostが必要。PLiCy・itch.ioなどの埋め込み配信では、その配信元のCSP・sandbox・ブラウザの保存方針にも依存する。公式サイトと各投稿サイトのキャッシュは別々であり、同じファイルでも配信先をまたいで共有はできない。

ブラウザの容量不足、利用者によるサイトデータ削除、プライベートモードなどによりキャッシュが消える可能性がある。永続保存や完全なオフライン起動を保証する仕組みではない。セーブ・既読・設定のlocalStorageには触れない。

## 更新時の運用

1. 素材を差し替えるリリースでは`VN_CONFIG.version`とHTML内のプログラム参照の`?v=`を更新する。
2. キャッシュしたまま同じバージョンの素材を上書きすると、既存プレイヤーには保存済み素材が表示される。公開修正もバージョンを上げる。
3. 配布ZIPは`tools/build_distributions.py`で作り直す。新規のローダーとService Workerを同梱し、itch.io向けのWebP変換・音声パックにも同じバージョン指定を適用する。

## 検証

- `node --test tools/check_asset_loading.cjs`：同時取得上限・現在素材の優先・分岐先の上限・失敗時の再試行・バージョン別キャッシュ・Range・保存拒否・古い非同期処理の無効化。
- `node --test tools/check_font_loading.cjs`：フォントCSSの待機、実際の本文の文字の読み込み、タイムアウト後の表示固定、未定義・取得失敗からの代替フォントへの切替。
- `py tools/check_asset_loading_browser.py`：新規Edgeプロファイルで初回取得、再読込時のキャッシュ、途中セーブ復元、実シナリオの先読み、バージョン更新を確認。結果・画像はリポジトリの隣の`stella-progressive-loading-check-20261026/`。
- 既存の`tools/check_distributions.py`は、起動時に全素材が取得済みであるという前提を持っていたため、遅延取得を含めた明示的な全素材検査へ分ける。

2026-10-27のローカルEdge確認では、ロード画面が待つ背景は2枚（合計172,454バイト）。起動直後の画像リクエスト全体は、ロゴとアイコンを含めて2,665,064バイトだった。変更前の先読み対象は223枚・約196.76MiB（設定と実ファイルの静的集計）。外部Webフォントと動画はこの画像容量に含めていないため、総通信量や公開回線での起動時間の比較ではない。

同じバージョンでの再取得抑制、Range再生、セーブの途中復元、実シナリオの先読み、バージョン変更での新規取得、遅延フォントの待機、タイムアウト後にフォントが届いても台詞幅が変わらないことを確認した。フォント試験はWindowsにインストールされた小さな試験用フォントをローカルで遅延配信し、実際の台詞欄の文字幅で判定する。フォント自体はリポジトリや配布ZIPに収録しない。

参考：[MDN Cache](https://developer.mozilla.org/en-US/docs/Web/API/Cache)、[MDN Caching](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Caching)。
