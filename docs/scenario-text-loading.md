# 本文キー表示の点検と修正（1.4.1）

2026-10-23。`chapter1.chapter1_lunch.pack_up` と `.pack_up.s002` が文章の代わりに表示される報告に対応。

## 調査結果

指摘の2行は手元・公開サイトの日本語・英語本文にどちらも存在する。公開サイトの本編12ファイル＋オマケを実取得し、章末の締めの文章も含めて日本語3,734件・英語3,917件を照合した。未定義参照・空の本文・本文値にID自体が入っている箇所は見つからなかった。点検時の公開バージョンは1.4。

従来の本文ローダーはJSON取得失敗を空辞書として扱い、未解決キーを `key` のまま返していた。シナリオ・本文を個別に通常のキャッシュ設定で取得し、読み込み後の参照検査もなかったため、不完全なデータや古い辞書が混ざるとそのままIDが画面へ出る経路がある。公開レスポンスのキャッシュ期限は600秒だった。

実ユーザーの発生時のブラウザー内データは取得していないため、個別事象がどのキャッシュ・通信状態によるものかまでは確定していない。欠けた辞書を意図的に返す再現試験で、この露出経路を修正・検証した。

## 修正

- 本文JSONとシナリオのURLに同じアプリのバージョンを付け、`cache: 'no-store'` で取得する。HTMLのプログラム参照にも1.4.1を付け、旧プログラムと新データの混在を防ぐ。
- JSON取得失敗・不正なJSON・空データ・ID自体の本文値を失敗として扱う。
- 本編とオマケの会話・地の文・選択肢・章タイトル・エンディング・締めの文章を全件照合してから開始する。不足や取得失敗があれば1回読み直す。
- 復旧しない場合は内部キーを出さず、日英の再読み込み案内を表示する。進行中に未解決の参照が見つかった場合も表示前に停止する。
- 再読み込みはセーブを消さない。本編プレイ中の未保存進行の離脱確認は維持する。本文そのもの・音声ID・音声ファイルは変更していない。
